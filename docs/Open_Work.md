## Technical debt

**Production cannot boot, on purpose.** `CONSENT_ADAPTERS` is an empty set (`apps/api/src/config.ts:274`) and `CONSENT_ADAPTER_FACTORIES` is an empty object (`apps/api/src/index.ts:91`), so `providers.consent` can never read `configured` and `APP_ENV=production` fails readiness. That is the right failure — a labeled development mock must never serve a real family — but it means the production path has never been exercised end to end, and it will not be until a consent vendor is contracted (owner action #7).

**No end-to-end test exists.** Zero tests drive a running stack. Every one of the 366 test files is a unit or integration test against a fake provider or a real local Postgres; there is no Playwright, no device harness, and no test that starts the Worker and the portal together. Any claim about the system as a whole is an inference from parts that each pass.

**Two mobile rules are pinned by source assertions, not behaviour.** The vitest project for `apps/mobile` cannot import `react-native`, so hooks that enforce parent/child separation are asserted against their source text rather than rendered (BUG-289, BUG-336). A refactor that keeps the strings and breaks the behaviour would pass.

**The bug ledger is past the size where it functions as a record.** `docs/Bug_Ledger.md` is one markdown table over 700 KB. It is complete and it is append-only on purpose, but it is no longer something a human reads, which is why this file exists. Splitting it by round is the obvious fix and has not been done.

**Response schemas are strict, so adding a field breaks installed apps.** Clients parse responses with `strictObject`, so a server that adds a field fails every client that has not shipped yet (BUG-420, accepted open with a named trigger). The first additive API change after a store release is a forced app update unless this is changed first.

**Three tests assert wall-clock budgets and fail under CPU contention.** `packages/domain/src/safety/screen.test.ts` has three cases that measure elapsed time and assert it is under 750 ms. On a 4-core container running a second full suite at the same time they measured 915 ms and failed (BUG-440). These are the awkward kind: the 750 ms is an assertion about the code's cost, not a harness timeout, so `scripts/check-test-timeout-margin.mjs` — which guards the whole suite against tests creeping up on their *timeouts* (BUG-442) — does not and cannot cover them. They were not weakened. A contractor who sees exactly these three red should check the machine's load before the code; anything else red is real.

**The records are large, numerous, and the thing that most needs discipline.** 442 ledger rows, 93 lessons, 49 owner actions and sixteen other documents in `docs/`. Four defects (BUG-411, BUG-426, BUG-430, BUG-432) were records that contradicted the code, not code faults. `docs/Source_Of_Truth.md` sets which documents bind and which are history; read it before trusting a sentence in `docs/`.

## What has never run

Every suite passes and nothing has ever served a request. These are different kinds of done, and
the second one is where the remaining risk is.

- **Any deployment.** No Worker, no portal, no native build has ever been deployed, to any environment.
- **Both deploy workflows.** `.github/workflows/deploy-api.yml` and `deploy-web.yml` have run zero times. They are code that has never executed; "it parses" is not "it works" (lesson L-085).
- **The migration workflow, and the hosted schema.** `.github/workflows/db-migrate.yml` has run zero times. The hosted Supabase project holds zero tables in `public`, `private` and `app` — the schema has never been applied anywhere but a local or CI database.
- **Every external provider.** OpenAI, RevenueCat, Stripe, Resend and the consent vendor have never been called with a real credential. Every provider test runs against a labeled mock or a fake `fetch`.
- **A native build.** No EAS build has been produced, so no store has ever seen a binary.
